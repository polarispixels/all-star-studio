# Star Shapes: Design

Date: 2026-10-04. Ships as **v0.4.0** (MINOR: a new page). This comes before the Team Members and Team Star work, so every later star is drawn on the shape Becky picks.

## Why

The contest's only rule is that entries may not use the Aetna/CVS heart. The heart's style (straight edges, rounded corners, a chunky friendly shape) can still inspire a star that feels at home next to the company look. The shape chosen here becomes the silhouette for Becky's star, Scott's Phoenix, the Detective star, and the team logo.

## Decisions (from review with Ryan)

| Topic | Decision |
|---|---|
| What she compares | About 5 star shapes. Each is shown plain **and** filled with her favorite kayak scene, at full size and at avatar sizes. |
| Avatar app | Unknown, so every shape is also previewed inside a **circle crop**, since most apps crop avatars to circles. |
| Contest rules | No Aetna/CVS heart. No other known rules. |
| Order | Ship this page alone first. Team Members and Team Star follow on the chosen shape. |

## The shapes

All shapes share the `0 0 1000 1000` viewBox, the same center, and the same outer reach, so only the corners and proportions change. Geometry is generated by `tools/build-shapes.mjs`: a five-point star whose outer tips and inner valleys are rounded with circular fillets, or flattened with chamfers.

| ID | Name shown | Idea |
|---|---|---|
| `classic` | Classic | Today's sharp star, as a baseline |
| `soft` | Softened points | Small rounding on tips and valleys |
| `chunky` | Chunky and round | Large rounded tips, like the heart's corners |
| `plump` | Plump | Shorter, wider arms (higher inner ratio) with rounded corners, closest to the heart's proportions |
| `boxy` | Squared-off | Tips cut flat with lightly rounded corners, a blocky look |

The generator also writes each shape's kayak version by taking the artwork group from `assets/prototypes/outdoors-illustrated.svg` and re-clipping it with the new silhouette and outline. If a plumper shape exposes empty edges, extend the scene's background shapes in the generator rather than hand-editing the output. Output goes to `assets/shapes/<id>.svg` and `assets/shapes/<id>-kayak.svg`, and the output passes the existing SVG checker. The checker's "shared star polygon" rule is relaxed for `assets/shapes/` so it accepts the shape's own path instead.

## `shapes/` page

- **Header:** "← Home". Title "Star Shapes". One line: "The contest can't use the company heart, so let's give our star the same friendly, rounded style. Which shape feels right?"
- **One card per shape:**
  - Name.
  - The plain shape and the kayak version side by side.
  - A row of small previews: kayak version at 48 px and 96 px, and inside a 96 px circle. The row is labeled "Avatar size".
  - A large tile, "This is my favorite shape". It's one radio group across all cards, with the check, the word "Chosen" and a thicker border, so selection never depends on color alone.
  - An optional "What would you change about this shape?" box (500 characters).
- **After the cards:** "None of these yet" as a tile in the same radio group, then an optional "Anything else?" box (1000 characters).
- **Send to Ryan:** the same pattern as Star Designs. Live summary, Share (where supported), Copy with a select-text fallback, Download summary (.txt), and Download data file (.json). Answers are saved under `all-star-studio.shape-feedback.v1`, with the same version-mismatch handling (`SHAPES_VERSION`).
- Look closer and SVG download are **not** included on this page, which keeps it short. The page shows sizes directly instead.

## Code

- Extract the shared UI helpers from `js/designs/page.js` into `js/ui.js`: element builder, inline-SVG instancing with id prefixes, tiles and tile groups, text boxes, downloads, and the Send section wiring. Both pages import from it. The Star Designs behavior is unchanged, and the browser check must still pass.
- `js/shapes/content.js` holds the shape list and labels. `js/shapes/feedback.js` holds the pure model: create, normalize, summary text, export JSON, and version check. `js/shapes/page.js` handles the DOM.
- Tests: `tests/shapes-feedback.test.mjs` covers skipped answers, summary accuracy, normalization, and version mismatch. `tests/svgs.test.mjs` is extended to the shape assets. `tools/browser-check.html` gains a shapes section covering selection, reload persistence, and the summary.
