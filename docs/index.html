What this suggests (proposals, not decisions)

  • She leans toward pictures: no idea got "colors and patterns" alone.
  • Her preferred workflow is describe the idea → see suggested colors → adjust.
  • Main tension: she wants rich detail, but Teams avatars and email signatures show logos at roughly 32–100 px, where fine details (the kayak paddler, the dumpster's face, the phoenix's eye) disappear. The final logo needs to read at small sizes.
  • The logo brands a team. It is still open whether the entry is one team star or a set of personal stars.

Open decisions and questions

  1. Confirm the contest deadline year (2026-10-22 assumed) and any brand rules for colors or shapes.
  2. Phoenix "a mix of both … Perfect": which version, or a blend?
  3. Her overall favorite design, and whether art may extend outside the star (both skipped).
  4. One team logo or personal stars per teammate?
  5. Next iteration focus. Proposed: refine 3–4 contest-entry candidates tested at Teams and email-signature sizes before building the general star maker.
  6. From the iteration brief: which modes (abstract, emblem, scene) belong in the product, and which symbols deserve reusable assets first.

Development at a glance

  • Static HTML, CSS, and ES-module JavaScript with native SVG. No build step, no backend, no external runtime resources.
  • Hosting is GitHub Pages from the root of the main branch. Every push to main deploys live.
  • Run locally with python3 -m http.server 8000. Run the tests with node --test 'tests/*.test.mjs'.
  • The release checklist is in CLAUDE.md: bump APP_VERSION in js/version.js, add a CHANGELOG entry, update this page (version badge, release table, status), tag vX.Y.Z, and push with tags. Tests fail if the version, the changelog, and this page disagree.
